## 발견한 문제와 수정

1. 동시 목적지 저장이 오래된 요청으로 덮어쓸 수 있었다. V6 revision·선행 조건 비교와 앱의 공유 등록 어댑터,
   한 번의 충돌 재조회로 보완했다. 목적지가 바뀌면 예전 검색 결과를 즉시 지우고 지연 응답도 무시한다.
2. 요청이 잠금을 기다리는 동안 계정 복구가 토큰을 폐기해도 최초 인증 결과가 남을 수 있었다.
   변경 작업은 계정 잠금 뒤 토큰을 다시 검사하도록 수정했다.
3. Mock과 실제 차량이 같은 방을 검색·참여할 수 있었다. 생성자·참가자의 출처를 비교하고 혼합 참가 이력을 만료한다.
4. 음성 서버 목록·생성 HTTP 요청이 전역 DB 잠금을 오래 보유했다. 비파괴적 IO는 트랜잭션 밖으로 옮기고
   토큰 반환 직전 참가·세션을 재검증한다. 삭제·제거 직전 권한 재검증으로 오래된 스냅샷의 오삭제를 막는다.
5. 방 검색이 미터 단위 거리를 노출했다. 응답은 최소 1km·1km 단위 올림으로 변경했다. 반경 판단과 거리순 정렬은 유지한다.
6. 앱의 방 상태 변경 후 이전 오디오가 남을 수 있었다. 서버의 방 ID가 바뀌면 기존 연결을 정리한다.
   손상된 Keystore는 인증 복구 안내로 분류하고, Mock VIN 최초 생성은 여러 제공자 간에도 원자적으로 처리한다.
7. 기존 화면은 상세 폼·개발 도구와 주 조작이 섞였다. 목적지·통화 중심 대시보드, 별도 입력 다이얼로그,
   수동 정차 확인, 최소 76dp 버튼과 주/야간 테마로 정리했다. 별도 패키지의 오프라인 체험 모드를 추가했다.
8. 클라우드의 PORT·PG TLS·Redis URL 설정을 보완하고 Docker/Render 초안을 추가했다.
9. 실제 음성 UI 테스트에서 마이크 발행 후 화면이 꺼짐으로 남는 경합을 발견했다. LiveKit 2.30.0의
   비동기 파생 속성 `isMicrophoneEnabled`를 직접 관찰하도록 수정하고 변경 실패 안내를 추가했다.
   [SDK 상태 정의](https://github.com/livekit/client-sdk-android/blob/v2.30.0/livekit-android-sdk/src/main/java/io/livekit/android/room/participant/Participant.kt)를 확인했다.

공통 API 계약은 [운행](trip-api.md), [통화방·음성](mvp-room-calls.md), 배포 전달 정보는
[Render·Firebase](deployment-render-firebase.md), 실행 결과는 각 저장소 `VERIFICATION.md`에 기록한다.

## 남은 제약과 출시 전 조건

- **VIN 소유권**: 클라이언트가 신고한 VIN·capability는 서명된 차량 소유권 증명이 아니다.
  `ownershipVerified=false`를 유지한다. 아직 연결되지 않은 실제 VIN의 최초 선점 방지는 별도의 신뢰 경로가 필요하다.
  공개 서비스 전 OEM 인증·차량 증명 또는 관리된 참가자 등록 방식이 필요하다.
- **목적지 개인정보**: 좌표·VIN은 방 검색에 노출하지 않지만 반복 거리·반경 검색으로 목적지를 추정할 수 있다.
  1km 근삿값만으로 완전한 위치 익명성을 주장할 수 없다. 공개 출시 전 요청 제한·보존 기간·계정 삭제·접근 감사를 정한다.
- **잠금 확장성**: 작은 MVP의 전역 잠금을 유지한다. 파괴적 LiveKit 관리 요청 한 건은 최대 5초 잠금을 보유할 수 있다.
  방별 잠금·작업 큐·다중 서버 부하 검증이 후속 과제다.
- **음성 수명**: 토큰 만료는 기존 미디어 종료가 아니다. 5초 주기 관리 API 정리에 의존하며 장애 시 종료가 지연될 수 있다.
- **차량 UX**: 정차 확인은 사용자 입력이다. 차량 속도·기어 기반 제한, 실차 화면 규격·오디오 포커스·Pleos 정책 검증은 남아 있다.
- **검증 환경**: 한 일반 Android 에뮬레이터 안의 세 실제 SDK 세션을 검증한다. 물리 단말 2~3대의 상호 청취,
  차량 스피커·마이크·노이즈·통신망 전환을 대체하지 않는다. 실제 Pleos 장비와 Render/Firebase 배포도 미실시다.
- **운영 준비**: TLS, 서명 키, DB 백업/복원, 모니터링·비용 알림·키 교체·남용 방지를 스테이징에서 확인한다.
  Firebase는 선택 배포·관찰 도구로 제안하며 PostGIS를 자동 대체하지 않는다.

현재 목표는 로컬에서 재현 가능한 MVP와 프로토타입이다. 위 조건은 공개 운영 적합성 판단과 구분한다.
